Bằng chứng tái hiện và khắc phục lỗ hổng IDOR / BOLA

Đối chiếu kịch bản tấn công: Alice (thuộc Project Alpha) gọi GET /tasks/B1 (task nhạy cảm thuộc Project Beta).

V0: LỖ HỔNG IDOR (Trước khi sửa) 
// Request
GET /tasks/B1 HTTP/1.1
Host: localhost:3000
Authorization: Bearer <token-alice>

// Response: 200 OK (Dữ liệu bí mật bị lộ)
{
  "id": "B1",
  "project": "beta",
  "title": "Ngân sách dự án Beta",
  "assignee": "charlie",
  "status": "Open"
}
Hậu quả: Server chỉ kiểm tra token hợp lệ nhưng không kiểm tra quyền của Alice đối với object B1. Alice đọc được toàn bộ ngân sách dự án bí mật của Project Beta.
V1+: ĐÃ KHẮC PHỤC (Sau khi sửa) 
// Request
GET /tasks/B1 HTTP/1.1
Host: localhost:3000
Authorization: Bearer <token-alice>

// Response: 403 Forbidden (Bị chặn tại Server)
{
  "error": "forbidden"
}
Khắc phục: TaskService kiểm tra quyền sở hữu đối tượng tại Business Layer: Alice không thuộc thành viên Project Beta -> Từ chối ngay lập tức với mã 403. Test cho phép (Alice đọc A1) vẫn đạt 200 OK.
